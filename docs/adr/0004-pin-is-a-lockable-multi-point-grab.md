# Pin 是可鎖定的多點 Grab——沒有「鎖定質心」模式

Pin 就是「目標點被凍結、不再跟指標」的 Grab：把某個表面點（重心座標附著）絕對鎖定在某個世界座標。數量不限，用力甩／Tap 都拔不掉，可拖曳重新定位。**不提供**「把 Jelly 質心絕對錨定」的獨立全域模式；要觀察「中心不動、拉一角到極限」的穩定態，就在質心附近放幾個 Pin。

## 為什麼

2026-09-02 的 grilling（Q11）與早期設計把 Pin 定為「每 substep 把擬合質心強制平移回原點，絕對錨定，單一」。後來釐清需求時，使用者要的是**任意位置、可多點**的釘選。而「一個鎖定的 Grab」本來就能「把某個表面點固定在某個世界座標」——ADR-0003 的重心附著軟約束，把目標點凍結即可。於是「多點任意 Pin」不需要新機制，只是「可鎖定的 Grab」。

真正的質心固定（每步 recenter）是另一回事：在質心放一個鎖定 Grab **不會**讓質心不動——仍可繞該點甩整個身體、拉遠端會把質心帶偏。保留它等於維護兩套機制（點約束 + 全域 recenter），且兩者與 Grab／Multi-grab 的組合語意要各自定義。

## Considered Options

- **保留 Centroid lock 當獨立模式**：給出更乾淨的「對稱拉到極限」觀察（質心數學上完全不動）。放棄它換「單一機制、少一組組合語意要定義」。多點 Pin 對這個 use case 已夠用。
- **Pin 完全等同 Grab、連「鎖定」都不特別標記**：不行——UI 與 Track（v2）需要區分「還在跟指標的 Grab」與「已凍結的 Pin」。

## Consequences

- `CLAUDE.md`「必備的沙盒功能」的「釘選模式」整段語意改變（多點、非質心）。
- 求解器：Pin 與 Grab 走同一條位置約束路徑，差別只在目標點是否更新。
- 輸入事件多出 `pin` / `unpin` / `movePin`（見 ADR-0005 的 `applyInput` 介面）。
