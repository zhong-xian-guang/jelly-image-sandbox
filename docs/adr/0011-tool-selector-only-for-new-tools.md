# 工具選擇器只涵蓋新增工具，Grab／Pin／Tap 維持手勢辨識

新增 Fan／編隊抓取／撒 Pin／移除 Pin 四個沙盒工具時，加了一個顯式的「目前工具」選擇器，但**只**在這四個新工具之間切換；Grab／Pin／Tap 三個既有操作**不**併入選擇器，維持原本純手勢辨識（拖曳＝Grab、快速點放＝Tap、鎖定用既有按鈕＝Pin）。選擇器預設值是「一般操作」，等同於維持這套既有手勢；切到任一新工具時，畫布手勢改由該工具接管，直到切回「一般操作」。

## 為什麼

2026-09-11 grilling 第二輪 Q8：新工具彼此手勢會衝突（例如「按下拖曳」在 Fan 工具下該解讀成放置風扇還是抓取），必須有辦法讓使用者明確表達「現在要用哪個工具」。但 Grab／Pin／Tap 已經上線、使用者已經習慣純手勢操作，若把這三個也塞進選擇器（每次要拖曳前得先確認選到 Grab），是對既有手感的破壞性改動，且沒有對應的使用者需求驅動這個改動。於是選擇「新工具走顯式選單、舊手勢維持原狀」這個不對稱設計，用選擇器解決新工具彼此的手勢衝突，同時不動既有部分。

## Considered Options

- **全部攤平進選擇器**：七種操作一致地靠選單切換，介面上更一致，但要求使用者在每次 Grab/Pin/Tap 前多一個選單操作，直接犧牲既有操作的流暢度，且沒有必要——Grab/Pin/Tap 三者手勢本來就不互相衝突（拖曳/快速點放/鎖定按鈕是三種不同手勢），不衝突就不需要顯式切換。

## Consequences

- 「目前工具」這個狀態只影響四個新工具；程式碼裡判斷「現在要不要把畫布手勢導去 Grab/Pin/Tap」的邏輯，等同於「目前工具 == 一般操作」。
- 之後若要新增第五個沙盒工具，預設規則是：只要它會跟 Grab/Pin/Tap 或跟其他新工具的手勢衝突，就加進這個選擇器；不衝突（像 Tap 之於 Grab）則不必納入。
