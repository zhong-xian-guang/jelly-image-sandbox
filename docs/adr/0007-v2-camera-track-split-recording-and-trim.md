# V2 素材工具：相機獨立成軌、錄製拆軌、加入頭尾修剪

（承 ADR-0006）V2 素材工具改為：一次錄製依「錄製目標」（只錄動作／只錄運鏡／兩者同時）產出**動作軌**與／或**相機軌**兩種 Track。相機不再混進動作的輸入流，而是自成一條或多條**相機軌**——每條自帶錄製當下的鏡頭快照，播放到其起始時間即**硬切**進場、再放它自己的相對位移量。相機軌之間在時間軸上不得重疊（軟警告，重疊區間只認先列那條）；動作軌之間可自由重疊（Multi-grab）。每條 Track 增加「頭尾修剪」（track 本地時間的 in／out 數字欄位）。播放加入「從頭播 + 暫停（全凍結：物理、秒數、鏡頭、事件全停）+ 目前秒數顯示」，**不做** scrub／seek，**不做**視覺化時間軸。

## 為什麼

實作 ADR-0006 的混合模型（一條 Track = 指標＋相機的單一輸入流）後，實際使用暴露三個問題：

- 使用者要分開錄「只做動作」與「只運鏡」的段落，但一次錄製難免混入另一種輸入；混合模型下這些雜訊會進到同一條 Track。
- 相機指令是相對位移量。多條各自從不同鏡頭位置錄下的 Track 疊加播放時，位移量套用的起點不明確（取最早那條？相加？），鏡頭會拍錯。
- 使用者的實際剪輯流程是「這段運鏡給 0–2 秒、下一段給 2–4 秒」的分段鏡頭，還要能錄鬆一點再修頭尾——ADR-0006 都沒有。

把相機獨立成軌、每條相機軌自我錨定（自帶起點快照 + 硬切），配合「相機軌不重疊」，就保證任何時刻最多一條相機軌絕對掌控鏡頭，起點永遠明確。錄製拆軌讓「只錄動作」的 take 天然不含相機雜訊。頭尾修剪用兩個數字欄位即可，不必畫時間軸。

## Considered Options

- **維持 ADR-0006 混合模型 + 疊加時取最早那條的鏡頭起點**：實作簡單，但多段運鏡疊加時鏡頭起點不明確、會拍錯，也無法乾淨分離「只錄動作」與「只運鏡」。
- **相機指令改記絕對鏡頭狀態（keyframe）而非相對位移**：起點不再有歧義，但兩條相機軌重疊時「哪個絕對值生效」又變成新問題，且與現有 `updateCamera` 的即時平滑模型衝突。
- **視覺化多軌時間軸（ADR-0006 已推遲的那種）**：更好操作，但畫 timeline canvas + 拖曳成本高，兩個數字欄位就能滿足分段與修剪。

## Consequences

- ADR-0006 的「錄一條輸入事件流（含相機操作）」與「只能整條刪除重錄、不做頭尾修剪」兩點作廢；其餘（不內建影片匯出、用 OBS、不做視覺化時間軸／波形、不管跨機器 bit 一致）仍成立。
- `#28` spec 需重寫（US2 相機錄進同一條 Track、Implementation Decisions 的「一條 Track = 聯集」、Out of Scope 的「不做修剪頭尾」）。`#29`（已 merge）的單一混合 Track 產出要改成拆軌；`#30` 的 commit 作廢（`mergeTracks`／`PointerId` 前綴邏輯留作實作參考，仍適用於動作軌之間的疊加）；`#31` 併入重切票。
- 「相鄰相機軌平滑銜接」（播放到下一段不硬切、改從當前鏡頭位置接續）列為每條相機軌之後可加的選項，這版不做。
