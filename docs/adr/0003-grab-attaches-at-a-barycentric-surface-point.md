# Grab 附著在表面的重心座標點，用軟約束——不吸附頂點

一個 Grab 抓住的是 Jelly 表面**使用者點下去的那一點**：picking 找出該點落在哪個三角形，記下重心座標 `(w0,w1,w2)` 當附著點。每 substep 算附著點目前位置 `p = Σ wₖ·xₖ`，把「目標 − p」的位置差按權重分回三頂點（`xₖ += β·wₖ·e / Σwⱼ²`）。被抓的 Particle **不設 `invMass = 0`、不直接搬位置**，照常參與積分、shape matching 與回推速度。

## 為什麼

grilling Q11 原本定的是「被抓 Particle `invMass = 0`，位置直接設為指標位置」。`/prototype`（`prototypes/shape-matching-feel.prototype.html`）實測發現兩個手感缺陷：

1. **所見非所得**：吸附到最近頂點，使用者期望抓的點與實際抓的點有肉眼可見的落差。
2. **一按就動**：抓到的頂點 ≠ 游標位置，下一 frame 硬把該頂點搬到游標 → 滑鼠一按下、物體立刻被拖曳，即使游標沒動。

重心附著點同時解掉兩者：附著點就是點擊處，按下當下「目標 == 附著點」→ 誤差為 0 → 零修正 → 游標不動則物體不動。軟約束（分回三頂點、不凍結 invMass）讓被抓處仍有速度，放開時自然就是 Fling，不需另外賦速；也移除了「單一被抓頂點無限剛性」的假影。

## Consequences

- 求解器的 Grab 介面是 `{三角形 (i0,i1,i2), 重心座標 (w0,w1,w2), 目標點}`，不是單一頂點索引。輸入層負責 picking（點擊命中哪個三角形）。
- 需要「點在所有三角形外」的退路：吸附抓半徑內最近頂點（重心權重 `(1,0,0)`）。
- `β`（Grab 硬度）是新的手感參數，初始 `1.0`（精準貼游標）；調低給彈性把手感。
- Multi-grab = 多條這種軟約束依序解，天然共存，不需特殊處理。
