# Backdrop 是世界空間的多張圖，存在瀏覽器 IndexedDB、不進片段檔

背景除了 Background color（填滿畫面的純色），新增 **Backdrop**：擺在世界空間裡的圖片，各自有位置、等比縮放與透明度，跟著相機平移縮放；可以有多張、疊放順序可調，一律畫在 Jelly、邊界線與提示之下。純視覺，不參與物理，相機跟隨也不納入它。

Backdrop 的原始圖檔（長邊超過 4096 px 先等比縮小）與各張的擺放參數存在瀏覽器自己的 **IndexedDB**，**不寫進片段檔**；IndexedDB 拿不到時退回成只在本次開啟有效，並提示一次。它也不是 Scene、不是 Track 事件：錄製中可以改但不被錄進去，停止／重設／清空全部都不動它。

## 為什麼

主要用途是錄素材時讓畫面有個像樣的佈景，而使用者的素材常有大範圍運鏡：

- **世界空間而非螢幕空間**：貼在螢幕上的背景在鏡頭推移時完全不動，看起來很假；跟著世界走，運鏡才有「鏡頭掃過場景」的感覺。
- **多張、可各自擺放**：只放一張世界空間大圖，Infinite 模式下 Jelly 一被甩遠就會看到圖的邊緣。允許多張、各自設定位置和縮放，使用者就能沿著預計的運鏡路線自己鋪好背景內容。
- **不進片段檔**：嵌入圖片會讓片段檔從幾 KB 的事件流暴增到數 MB，還得處理格式版本遷移。使用者通常在同一台瀏覽器反覆錄素材，佈景留在本機就夠用。
- **IndexedDB 而非 localStorage**：localStorage 約 5M 字元，一張照片轉成 base64 就可能塞爆；IndexedDB 能直接存 Blob，容量大得多。兩者一樣「只屬於這台瀏覽器」，語意不變。

## Considered Options

- **螢幕空間（像桌布一樣固定鋪滿）**：最簡單，但運鏡時背景不動，錄出來的素材很假——否決。
- **視差（背景按一個比例跟著相機移動）**：有景深感、也不會露出邊緣，但使用者沒辦法精確控制鏡頭掃到哪裡會看到什麼——否決。
- **單張世界空間大圖**：Infinite 或大範圍運鏡時一定會露出邊緣——否決，改成多張。
- **寫進片段檔**：佈景跟著片段走、分享時也帶得過去，但檔案膨脹又要處理遷移——v1 不做，日後真的有分享片段的需求再重新檢視本 ADR。

## Consequences

- 把片段檔帶到另一台瀏覽器打開，看不到原本的 Backdrop。這是預期行為。
- 背景圖的貼圖走瀏覽器原生 `<img>`，所以瀏覽器解得開的格式都收（含 webp／avif）。這不違反 ADR-0009：那份 ADR 只約束 mesh 端的 alpha 解碼。
- 工具列多了一個「背景圖」工具（ADR-0011 允許新工具加入工具列）：左鍵拖曳移動；按住右鍵＋滾輪調整，中鍵在「縮放」與「透明度」兩個模式之間輪替，做法跟風扇一樣；右鍵單擊開選單（刪除、移到最上層或最下層）。Picking 依矩形範圍判定，選中游標底下最上層、目前顯示中的那張；圖片透明的地方也算點中。
