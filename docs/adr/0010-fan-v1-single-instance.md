# Fan v1 只做單一實例——不跟 Pin 一樣數量不限

Fan（電風扇，見 `CONTEXT.md`）v1 場上同時只有一個：畫布上再拖曳一次放置手勢，直接取代舊的 Fan（位置／方向／長寬全部覆蓋，強度／衰減沿用面板上次數值）；面板另有一個「移除風扇」按鈕可以回到沒有 Fan 的狀態。不像 Pin「數量不限」。

## 為什麼

2026-09-11 grilling 第二輪 Q3 時使用者明講「工具不要太複雜，先一個風扇就好」。Fan 比 Pin 多了方向、長寬、強度、衰減四個參數，若也做成數量不限，就得再設計一套「選取哪個 Fan／逐一編輯／逐一刪除」的管理 UI（Pin 靠的是點約束本身輕量、Track 也已經有「清除 Pin 事件」這種批次操作打底）。刻意先不做這套管理介面，用「直接取代」把心智模型簡化成「場上最多一個 Fan，這個按鈕負責它的存在與否」。

## Consequences

- Fan 的放置／取代／移除都不需要「選取哪一個」這一步，Track 錄製的 Fan 相關事件也只需描述「目前這個 Fan 的狀態」，不需要攜帶 id。
- 之後如果要做多 Fan，需要另外設計選取／管理 UI，且要重新考慮 Track 事件是否要帶 id 才能分辨錄的是哪一個 Fan——不是無痛擴充。
