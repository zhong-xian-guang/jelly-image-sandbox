# 重力是一條拉霸而非模式：0 = 俯視無重力，> 0 = 側視——推翻 ADR-0001 的情境前提

加入 **Gravity（重力）** 拉霸（見 `CONTEXT.md`）：最左 = 0 = 現況（俯視、無重力，Jelly 靜置即靜止），往右拉越重，所有 Jelly 持續被往畫面下方（世界座標 +y）拉。**沒有**獨立的「重力模式」開關，方向固定向下、不可調角度。重力是片段設定（存進片段檔、整段固定），不是 Track 事件。

配套：Boundary 新增第三種 **Floor**（僅地板，左右與上方無限）；切換當下地板貼齊場上 Jelly 的最低點，讓 Jelly 一切過去就已站在地板上（與 Walled 依 bbox 展開範圍同一思路）。牆與地板一律套**切線摩擦**（固定手感值、不給拉霸），不分地板／牆。

## 為什麼

ADR-0001 與 `docs/design/simulation-and-mesh.md` 寫死「俯視、無重力」，Fling 靠阻尼收斂。2026-09-16 grilling 使用者提出重力需求（帶拉霸調大小 + 僅地板邊界）。這等於把情境從「桌上一塊果凍」擴成「也可以是側視、掉在地板上的果凍」。未來讀者看到俯視桌面遊戲裡有重力會覺得矛盾，因此記下：**俯視仍是預設**（拉霸在 0），重力是使用者主動開的擴充情境，不是改變產品定位。

拉霸而非「開關 + 拉霸」：少一個狀態；「拉霸在 0」比「開關關著」更直覺看出沒重力；也避免「開關開著但拉霸在 0」這種無意義組合。

摩擦：有重力 + 地板後，Jelly 被甩出去會在地板上無摩擦滑行，只靠全域阻尼慢慢停，看起來像冰面。摩擦先固定值不開拉霸——先求手感對，需要再開。

## Considered Options

- **重力模式開關 + 強度拉霸**：多一個狀態、多一種無意義組合，見上。
- **可調重力方向（角度）**：沒有需求；方向固定向下讓 Floor 邊界的定義（一條水平地板）保持簡單。
- **重力錄成 Track 事件（播到一半才開）**：有趣但沒需求，且會把 Softness 等其他片段設定也拖進「要不要能錄成事件」的重新設計。
- **Floor 的地板固定在世界某個 y**：Jelly 切過去可能憑空掉一段或半截埋在地板下；貼齊當下最低點沒有這問題。

## Consequences

- `docs/design/simulation-and-mesh.md` 的「情境前提」與 substep 第 1 步「外力（v1 只有無）」要改：外力 = 重力 × 質量，重力預設 0。
- Boundary 介面多一個實作 `Floor`；`BoundaryMode` 多 `'floor'`；片段檔 `sim.boundary` 接受三值、多一個 `gravity` 欄位。
- 重力 + Infinite 邊界會讓 Jelly 永遠往下掉、相機永遠跟——允許，這是使用者自己的組合，不做特殊處理。
- 阻尼原本調到「放手後 1–2 秒靜止」；有重力時靜止的定義變成「落在地板上不再動」，摩擦與阻尼要一起重新實測。
  - **追記（issue #91，2026-09-18）**：實測決定**不動阻尼**（0.02／substep；改它舊片段重播就變），改把拉霸上限從初訂 2000 拉到 10000 換取落體速度；數據在設計文件參數表。另發現 shape matching 跨 Region 等權平均會漏動量，有重力時靜置在無摩擦地板上會一路滑走——`gravity ≠ 0` 時開動量守恆修正，`gravity = 0` 走原路徑保住舊片段位元重現（要不要全域開啟見 issue #102）。
- 場上沒有 Jelly（清空全部之後）時 Floor／Walled 範圍維持上一次算出的值，不重算。
