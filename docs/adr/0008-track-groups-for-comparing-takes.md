# 用群組分組 Track、逐一比較各版效果

素材工具原本只有一種播放：所有 Track 依起始時間與修剪疊加成一段素材（ADR-0006／0007）。實際使用暴露一個缺口：使用者常錄好幾版候選操作，想**各自播放來比較**、挑出最好的一版，而不是全部疊在一起。

決定：加入**群組（Group）** ── 把已錄 Track 分組的具名容器。多對多（一條 Track 可屬多個群組）、每個群組帶開啟／關閉狀態；播放取所有**開啟中**群組的成員 Track 聯集，照既有 Overlay 規則播。逐一開關不同群組再重播，就能比較各版。永遠有一個**預設群組**收納新錄好的 Track，預設開啟 ── 不手動分群時行為與今天完全相同（全部 Track 一起疊加）。

## 為什麼

- 「比較各版效果」是真實需求，但硬做「並排同時播兩版」要兩套 Jelly 與相機，違反 ADR-0007「transport 維持最小、不做視覺化時間軸」的立場。逐次比較（開一組、播、`停止／重設`、換一組、再播）用一個開關就能滿足。
- 分群是**進階、不常用**的操作。預設群組 + 預設開啟讓沒在分群的使用者感覺不到這個功能存在，播放行為零變化。
- 多對多讓「同一段運鏡配 A 版或 B 版動作」這種情境不必重錄 ── 那條 Camera Track 同時掛在兩個群組即可。
- 難邏輯不進 `mergeTracks`：群組歸屬只是「扁平 Track 清單」上的一個過濾條件，`playAll` 呼叫 `mergeTracks` 前先濾掉不屬於任何開啟中群組的 Track，輸入順序不變（決定性、「先列」語意不受影響）。

## Considered Options

- **群組＝互斥的變體（一次只有一個生效）**：概念直觀，但「同時疊多條做 Multi-grab」是 Track 存在的核心動機（見 CONTEXT.md），互斥模型下就得另立一套「非變體」機制。可開關的多對多束把「單獨播一版」與「疊多組」收在同一個規則裡（開啟中聯集）。
- **每次錄製自動開一個新群組**：比較用的結構錄完就現成，但使用者明確表示分群不常用、不想每次錄製都多一個群組要收拾。改為新錄製一律進預設群組，要比較才手動建群組、搬 Track。
- **只開一部分群組時把時間軸重新對齊到最早的那條**：比較單一群組時不必每次手動把起始秒數歸零，但「起始秒數」的意義會隨「開了哪些群組」浮動。維持絕對起始時間；「播放時全部從 0 開始」若真的需要，另做一個獨立的總開關。
- **並排同時播多版**：見上，範圍外。

## Consequences

- ADR-0007 隱含的「所有 Track 一起疊加」收斂為「開啟中群組的成員聯集一起疊加」；預設群組 + 預設開啟保證預設行為不變。CONTEXT.md「Overlay」詞條隨之修一句、新增「群組」詞條。
- 新增記憶體狀態：群組清單（名稱 + 開關）、Track↔群組多對多歸屬。生命週期比照 Track 清單（`停止／重設` 保留、重新匯入 PNG 清空）。
- 群組概念不分 Track 種類。本 ADR 對應的票只對 Action Track 清單實作分群 UI；Camera Track（#36／#37）之後接進同一套群組區。相機軌「不得重疊」檢查改對「開啟中聯集」在播放當下判定。
- 刪除群組只解除歸屬，成員 Track 不刪；掉到 0 群組的 Track 自動回預設群組（維持「每條 Track 永遠至少在一個群組」的不變式）。
- 排序：#28 的 sub-issue，blocked by #33，排在 #36 之後、#37 之前（讓 #37 一併處理開啟中聯集的相機軌重疊）。
